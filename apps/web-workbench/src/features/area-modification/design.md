# 任务情境交互原型设计草案（Issue #222）

状态：草案。本文是 Issue #222 要求的第一个交付物：场景事实说明、业务依赖表、S1-S5 初版规则决策表基线。
所有业务事实均为模拟，标注为"待业务核实"的假设不得当作真实业务结论。
实施中每次修订规则基线时，记录版本与改动原因。

## 1. 范围与边界

- dev-only 原型，入口复用现有模式：`import.meta.env.DEV` + URL query 参数 + `defineAsyncComponent` 异步分包（参照 `App.vue` 中 scenario-lab / map-trace prototype 的接入方式），生产构建不可开启。
- 实现位置：`apps/web-workbench/src/features/area-modification/`。
- 规则模块为纯 TypeScript：输入情境、输出交互需求，不依赖 Vue、DOM 或网络。
- 不接真实 LLM / Agent / SACS；不增加 Runtime 职责；不新建共享 package。

### 现有能力摸底结论（2026-09-15）

| 原型需要的能力 | 现状 | 处理方式 |
| --- | --- | --- |
| 点选地图上已有区域 | 缺失，无可复用的面图层点击 | 复用 `map-controller.ts` 中 hit-layer + `queryRenderedFeatures` 的既有模式新增 |
| 现场绘制新区域多边形 | 缺失，无任何绘制库依赖 | 自绘轻量交互或引入 terra-draw，实施前单独决策 |
| 拖动编辑区域边界（单条边/顶点） | 缺失，无可拖动标记与 `setData` 变更 | 新增，仅服务本原型 |
| dev-only 入口、场景重置、事件注入 | 已有可复用模式 | 直接照搬 scenario-lab / map-trace prototype 的做法 |
| 高亮、聚焦、图层显隐 | 已有稳定能力 | 直接复用 |

新增地图交互遵守现有 `MapView.vue` 的 props-in / events-out 契约，不绕过组件直接操作 controller。

## 2. 场景事实说明（全部为模拟）

主场景：巡逻任务 T-001 正在执行，原定巡查区域 A（复用现有 `north-corridor` 北走廊数据）。
用户提出新增区域 B，同时保留 A 的原要求。

### 2.1 任务与责任

| 事实 | 值（模拟） | 备注 |
| --- | --- | --- |
| 任务 T-001 状态 | 执行中 | 模拟 |
| 当前责任 | 任务负责人（即当前用户） | 模拟 |
| 模拟提交权限 | 当前用户可提交修改 | 待业务核实权限模型 |
| 区域 A 原要求 | 频次 2 次/日、覆盖全边界、单次时限 2 小时 | 保留，不因新增 B 而丢失 |

### 2.2 候选区域（带来源标记）

| 候选 | 来源 | 边界 | 备注 |
| --- | --- | --- | --- |
| B1 东侧库房 | 数据库已有 | 已有 | 含糊指代"旁边那块"的候选之一 |
| B2 南侧堆场 | 数据库已有 | 已有 | 含糊指代候选之一 |
| B3 区域 2 | 数据库已有 | 已有 | 指名道姓"把区域 2 也巡一下"直接命中 |
| B4 区域 3 | 数据库已有 | 已有 | 同上 |
| 新区域 N | 用户现场绘制 | 来自绘制动作 | 数据库无记录，需补充名称 |

### 2.3 必要输入

| 输入 | 适用条件 | 用户可提供 |
| --- | --- | --- |
| 巡查频次 | 任何来源的 B | 是 |
| 时段窗口 | 任何来源的 B | 是 |
| 区域名称 | 仅来源为现场绘制时 | 是 |
| 限制区叠加判定 | 任何来源的 B | 否，只能等待后台核实 |

### 2.4 检查项（确定性模拟检查）

| 检查 | 依赖输入 | 模拟结果逻辑 |
| --- | --- | --- |
| C1 时长检查 | B 边界、频次、时段 | 边界面积 x 频次系数估算超出时段窗口则判冲突（系数待业务核实） |
| C2 限制区检查 | B 边界 | 与现有 `north-restricted-zone` 多边形相交则判冲突 |

检查结果必须关联其所依据的输入版本号。
旧版本结果、重复送达的结果、已结束事项的迟到结果不得覆盖当前有效结果。

### 2.5 冲突与可用修改选项（后台明确提供）

| 冲突 | 可用取舍 |
| --- | --- |
| C1 时长超限 | 缩小 B 边界 / 降低频次 / 压缩时段 / 放弃新增 |
| C2 限制区重叠 | 调整 B 边界 / 放弃新增 |

## 3. 业务依赖表

业务依赖是场景数据，不是交互规则。换一个业务场景时本节整体替换，第 4 节规则不变。

| ID | 变化或事实 | 影响 |
| --- | --- | --- |
| D1 | B 边界变化 | C1、C2 的既有结果失效，需按新版本重查 |
| D2 | 频次或时段变化 | C1 的既有结果失效 |
| D3 | 来源为现场绘制 | 必要输入增加"区域名称" |
| D4 | 设备位置等无关事实更新 | 不影响任何检查与编辑状态 |
| D5 | C1 / C2 判定冲突 | 生成待取舍事项，附带 2.5 节对应取舍选项 |
| D6 | 后台核实新证据消除待决定事项 | 该事项不再适用，进入收尾 |
| D7 | 提交时刻 | 由模拟业务边界按当前输入版本重新校验，区分已接收 / 处理中 / 已确认 |

## 4. 交互规则决策表（初版基线 R1-R9）

规则描述的是与业务无关的交互模式。
每条规则只读情境事实、输出交互需求；允许多条同时命中，输出为集合，不压成固定步骤条，不只返回第一个命中。

| ID | 触发条件（对情境的判定） | 交互需求输出 |
| --- | --- | --- |
| R1 | 范围指代解析出多个候选，或未明确 | 提供候选澄清：列表 + 地图高亮 + 点选 / 绘制入口；不替用户确认 |
| R2 | 存在用户可提供但未填的必要输入 | 提供对应输入能力，突出缺项，保留其余内容 |
| R3 | 范围明确且无缺项 | 直接进入所需检查，不输出澄清与补参 |
| R4 | 某输入版本递增 | 按业务依赖表仅使依赖该输入的检查失效，无关检查保持有效，用户已填内容保留 |
| R5 | 当前输入版本的检查运行中 | 说明由系统处理中，保留仍可用的编辑入口 |
| R6 | 当前有效版本的检查结果为冲突 | 展示依据与实际可用取舍；不得将冲突渲染成缺项 |
| R7 | 事件不命中任何业务依赖 | 仅更新对应事实，保持编辑焦点与地图视口 |
| R8 | 新证据使待处理事项不再适用 | 说明原因，结束或更新该事项，草稿保留可查看，旧操作提交失效 |
| R9 | 信息只能等待后台核实 | 标记未知并说明等待依据，不要求用户猜测，允许保存草稿与查看全部内容 |

### 4.1 S1-S5 与规则的对应（基线验证目标）

| 场景 | 预期命中 | 说明 |
| --- | --- | --- |
| S1 含糊指代多候选 | R1 | 选择前不擅自确定范围 |
| S2 范围明确缺一项参数 | R2 | 只突出缺项输入 |
| S3 输入齐全 | R3 | 直接检查，无重复补参 |
| S4 后台确认冲突 | R6 + D5 | 解释取舍并提供修改入口 |
| S5 修改 B 的一条边 | R4 + D1 | 依赖边界的检查失效，无关检查保持，输入保留 |

### 4.2 并存问题处理

缺项与冲突可同时存在（S8）。
规则输出按事项组织：每个事项携带当前问题、可用交互能力、阻塞原因、相关依据、保留内容、失效检查。
事项之间的并行 / 等待关系由业务依赖表说明，不由规则硬编码顺序。

## 5. 禁止事项（实施自查清单）

- 禁止按场景名、fixture ID 或整套状态组合选择硬编码交互流程。
- 禁止把本应属于规则的逻辑转移到配置或 adapter 中冒充复用。
- 旧输入版本的检查结果不得恢复旧预览、旧冲突或旧提交资格。
- 规则计算与页面重渲染不得重复提交或重复触发相同检查。
- 前端校验不代表真实业务授权；提交以模拟业务边界重校验为准。
