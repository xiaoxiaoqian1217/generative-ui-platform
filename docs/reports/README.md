# 验证报告

`docs/reports/` 用于保存由多次实验与已有证据汇总形成的阶段性验证报告。

报告不是 Demo 清单，也不以功能完成度代替交互结论。

## 报告需要区分

- 已经观察到的事实；
- 当前判断；
- 反例与限制；
- 适用边界；
- 尚未验证的推断。

详细 Evidence Level、Research Question 和假设需要时可追溯到 Research Protocol，但报告面向决策时优先表达“我们验证了什么、得到了什么、哪里还不能下结论”。

## 最终成果分两类

### 1. 交互知识资产

多个 EXP 中稳定的发现应整理为：

- 交互模式定义；
- 标准交互流程；
- 设计原则；
- 适用边界；
- 可迁移场景。

### 2. 可复用技术资产

已经证明值得复用的工程能力应整理为：

- 可复用交互能力；
- 状态 / 协议约定；
- Frontend / Runtime 实现；
- Scenario / Fixture；
- 自动化测试与可观察证据。

技术资产只有在确实能够支持相应 Interaction Mode 时才进入报告，不为了“平台化”提前抽象。

## 地图阶段报告

计划阶段报告：

`AGENT-USER-INTERACTION-MAP-VALIDATION-REPORT.md`

报告按 Interaction Mode 汇总：

```text
委托执行
征询等待
工具中介行动
打断纠偏
↓
交互知识资产 + 可复用技术资产
```

单轮问答作为已有基础能力，不单独形成地图 EXP。
