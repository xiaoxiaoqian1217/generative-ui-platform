# 选题评审报告：研究价值与专利可行性

> 日期：2026-09-29｜性质：选题阶段评审意见，非专利法律结论、非授权前景保证。
>
> 评审对象为本目录 01-09 全部文档，重点依据 [03 专利对比](03-patent-comparison.md) 的 F1-F8 特征矩阵与 [04 创新路线](04-innovation-roadmap.md) 的候选组合。评审时的网络检索工具不可用，涉及公开时间的判断均保留为待核事项。

## 1. 总体结论

1. 选题有意义，工程落地价值高于学术贡献价值。
2. 作为 HAI 领域专利可行，但成功形态不是"动态交互组织专利"，而是"带外部副作用的运行中 Agent 任务的受控介入与恢复方法"。
3. 核心锚点应放在 F8（按运行依赖失效范围确定恢复位置并处理外部副作用），F3/F5/F6 作为从属递进。
4. AG-UI 已由项目方确认在申请日前长期公开，F5/F6 的宽权利要求不成立，权利要求必须收窄到协议未覆盖的范围。
5. 申请前必须解决的两个风险：P6 优先权日期核查、真实恢复链的充分公开。

## 2. 研究价值判断

### 2.1 成立的部分

问题真实且时机合适。

运行中 Agent 找人协作时"该看什么、能改什么、改完会怎样"是 2026 年各 Agent 产品普遍遇到但没有标准解法的问题。

HAI 文献（Amershi 2019 准则、Horvitz 混合主动）只给出设计原则，没有给出可执行机制。

方法论质量高。

需求准入（[07](07-real-inspection-needs.md) 取证）、公平对照（B1 通用编辑对 B2 情境化）、用户侧与系统侧消融分离、负结果记录，在专利研究中保持了少见的纪律性。

R1-R7 需求框架卡住了"为做专利而编需求"的退路。

### 2.2 需要泼冷水的部分

学术贡献偏弱于工程贡献。

首版明确不用 LLM、以规则和受控组件实现，在 HAI 学术圈属于系统机制工作。

认知层面的新意（用户理解范围）是验证指标而非发明点。

如果用户实验显示 B2 相比 B1 无显著差异（计划本身承认这是可能的），学术故事不成立，但工程价值仍在。

"最小充分信息组织"不适合作为权利要求。

它本质是 UX 原则，[04](04-innovation-roadmap.md) 已将其降级，建议保持降级，只做效果说明。

选题的本质创新密度集中在机制链，而非交互现象。

应接受它更接近软工专利，而非交互范式专利。

## 3. 专利可行性

### 3.1 客体适格性

"运行中任务状态 - 计算允许修改集合 - 组织界面 - 提交校验 - 原子接纳 - 依赖失效 - 受限恢复"是有明确数据处理步骤的方法链。

中国发明客体没有障碍。

美国方向存在 Alice 抽象概念风险（"组织界面"易被认定为抽象想法），但机制锚点（条件更新、幂等记录、失效标记、恢复事件）是技术性手段，认真撰写可以通过 101。

### 3.2 权利要求锚点分析

F1、F2、F4、F7 在对比矩阵中均已有"明"或"近"的公开。

"动态组织界面"作为独立权利要求的锚点已被 P1/P2/P5 围死，不可辩护。

真正有空间的特征及其判断如下。

| 特征 | 矩阵状态 | 评审判断 |
| --- | --- | --- |
| F3 从协同需求临时推导可修改集合 | 全部"未" | 有空间，但需证明不是"权限表 + 字段白名单"的换名，差异在执行情境参与计算 |
| F5 介入界面与语义前置条件绑定、提交时重验 | 全部最多"近" | 有空间，P6 的基线校验与常规乐观并发控制构成组合压力 |
| F6 条件变化使旧介入失去操作资格 | 全部最多"近" | 单独看是已有技术（乐观锁、过期审批），必须与"相关状态读集合"绑定才站得住 |
| F8 按运行依赖失效范围确定恢复位置 + 外部副作用处理 | 全部"未"，矩阵中最干净的一格 | 最该锚定的核心。检查点、增量计算、工作流恢复各有积累，但"人的修改 - 依赖传播 - 执行器侧恢复边界选择 + 副作用核查"这条链在 6 件对比专利中无完整覆盖 |

### 3.3 组合层面的辩护叙事

AG-UI 已确认为申请日前长期公开的现有技术。

协议覆盖了中断生命周期、工具绑定、`editedArgs` 全量替换、过期与幂等恢复等基础能力，因此 F5/F6 的宽表述不可主张。

协议刻意不覆盖的部分是差异空间：从协同需求推导临时可修改集合、语义前置条件的读集合、提交时的服务端影响分析、依赖失效传播、执行器侧恢复边界选择、外部副作用核查。

独立权利要求应站在 F8 上，把 F3/F5/F6 作为从属递进。

核心区别技术特征是"同一份介入约束描述贯通界面组织、提交校验、恢复反馈三端"（见 [04 第 3 节](04-innovation-roadmap.md)）。

辩护逻辑不是任何单点机制新，而是同一约束在三端的贯通关系新。

### 3.4 申请前必须解决的两个风险

1. P6 的优先权日期差异（2024-11-19 还是 2025-11-19）。

差一年直接影响它能否作为现有技术评价本方案。

1. 充分公开。

首版执行器为 Mock，如交底材料只有模拟回放，无法支撑"受限恢复"的实施例。

动作：至少跑通一条真实链路（AGUIMock + 真实 LangGraph 图），对恢复锚点、失效传播、副作用核查各做一次真实执行并留事件轨迹。

### 3.5 时间窗口

领域拥挤且授权前公开很快（P4 于 2026-03 申请、2026-04 公开）。

不能等用户实验做完再申请。

[05](05-literature-plan.md) 已允许交底草稿先描述尚无效果数据的真实机制，因此 P0/P1 取证与交底撰写应并行。

达到 K2（机制链可解释）+ K3（正反例可重现）即具备提交条件。

## 4. 大白话摘要

专利解决的问题：AI 干活干到一半来找人帮忙时，让人知道"这次要我干嘛、我能改什么、改完会怎样"。

已有专利做过的（不可主张）：按情境换界面、任务模型驱动界面、人改参数继续跑、版本过期拒绝。

真正没被人完整做过的（应主张）：人改完一个决定后，系统精确算出"哪些旧结果还有效、哪些作废、从哪个合法位置接着干、已经发出去收不回的动作怎么处理"。

一句话定位：不押"动态界面"，押"带外部副作用的运行中任务的精确恢复"。

如果后续检索发现 F8 也有完整公开，退路是收缩到"介入约束三端贯通"这一个关系特征（[04 第 9 节](04-innovation-roadmap.md) 的收缩分支），专利价值变薄但仍可能成立。
