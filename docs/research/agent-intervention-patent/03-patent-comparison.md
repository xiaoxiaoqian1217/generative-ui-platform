# 相近专利检索与技术特征对比报告

版本：0.1｜核验日期：2026-09-29｜性质：选题阶段证据报告

## 1. 本轮结论与使用边界

本轮重新打开了此前讨论中的 **6 件专利全文页面**，编号和名称均得到核实。检查范围包括权利要求及相关说明书；其中的机制公开不能直接等同于产品已经实现，也不能把申请公开文本当成最终授权范围。

现有材料足以削弱“动态生成 UI”“人在环修改参数”“绑定对象后恢复”“版本不一致时拒绝”等宽泛创新表述。当前值得进一步研究的，是**一次协同需求怎样同时约束界面组织、允许修改范围、提交条件和后续执行影响**。这仍是差异假设，尚未证明具有新颖性或创造性。

特别修正此前讨论中的三种表述：

- **不能因为本轮没有找到完整链条，就认定组合具有创造性。** 还要检查相邻领域的组合启示、公开时间和具体技术效果。
- **不能把某个从属权利要求的限定扩大成整件专利的唯一实现。** 例如下文 P4 的重新初始化路径属于权利要求 8，不能据此声称其全部技术方案均排除局部恢复。
- **说明书公开与权利要求保护范围要分开。** P5 中的监督、反馈内容来自说明书；其独立权利要求 1 的中心是多层记忆与学习偏好。

本报告不是授权前景保证或实施自由分析。所用 Google Patents 页面是专利公开文本的检索入口；未完成各国官方案卷、审查意见、权利转移和完整同族核查。页面所列法律状态不作为当前有效性结论。

## 5. 最需要面对的组合压力

以下是本报告提出的**检索与反证假设**，不是已认定的法律结论。

| 可能的组合思路 | 为什么会对本方案形成压力 | 下一轮需要寻找的实质差异 |
|---|---|---|
| P2 的任务数据/界面映射 ＋ P3 的执行中人机协同 | 可能覆盖“任务上下文确定表单，用户改完继续”的普通组合 | 同一协同需求如何导出对象、可写集合和必要信息；导出规则是否超出手工配置 |
| P2/P3 ＋ P6 的基线与局部编辑处理 | 容易将状态绑定、过期提示和保留无关修改理解为常规并发编辑手段 | 哪些**语义前置条件**改变才使界面失效；如何避免无关状态更新误伤；是否与执行依赖共同判定 |
| P4/P5 ＋ 检查点、增量计算、工作流恢复资料 | “人工反馈后从中间继续”本身未必特殊 | 修改是否穿过已执行外部动作；哪些结果可复用；恢复边界如何证明正确 |
| 上述组合 ＋ 表单 Schema、受控组件 | “最小充分 Surface”可能只是字段筛选的另一种称呼 | 用可检验规则保证必要证据和操作完备，同时排除不相关内容，而非主观减少按钮 |

因此，应停止使用“临时 UI 与持久 UI 不同，所以有创新”这类单点论证。界面存活时间是可配置属性；需要说明它怎样与操作资格、任务对象变化、执行恢复共同约束同一次用户介入。

现行 AG-UI 协议基础也削弱单独的绑定/恢复主张，具体见[技术方案第 4.5 节](02-interaction-model.md#45-与现行协议和执行框架的衔接)及[官方 Interrupts 文档](https://docs.ag-ui.com/concepts/interrupts)（核验：2026-09-29）。该网页的首次公开日期尚未核实，当前用于设计基线与检索线索，不据此倒推历史披露时间。

## 6. 下一轮要补的证据

1. **确认比较对象的时间边界。** 保留每件公开版本、优先权文件和同族关系；优先解决 P6 日期差异。正式判断现有技术时，再结合拟申请方案的有效申请日处理。
2. **查运行系统而非只查 UI。** 检索工作流迁移、人工修改检查点、依赖失效、增量恢复、并发审批和重复提交处理，寻找与 F3/F5/F8 对应的实现。
3. **查 UI 语义范围的生成。** 搜索由目标对象、操作目的、任务依赖共同推导可编辑集、证据集和界面组件的方案；不仅搜索 Intervention 或 Surface 这两个自定术语。
4. **核对非专利公开。** 对协议、开源实现和论文记录版本/提交/出版日期，不把“今天能打开”当成“某日前已公开”。
5. **用完整实施例反查。** 以“运行中修改一个工具参数”为最小案例，列出读集合、写集合、前置条件、失效集合、恢复位置及副作用，逐项查是否已有对应披露。

## 8. 阶段性建议

保留智能交互主线，把工程基础能力与候选差异分开。下一步最有价值的产物不是继续增加专利标题，而是一个可复查的例子：**为什么这次只出现这些信息和操作；为什么当前仍允许提交；提交后哪些结果改变、哪些保留；无法局部恢复时怎样明确反馈。**

只有该例子形成了可实现规则，才能把本报告中的差异假设改写成清晰的技术特征，再交由后续检索和专业审查反证。

这使“人工复核异常、补充取证、改变检查安排”成为必须面对的已有公开内容。找到真实应用需求不等于找到专利空白。下一轮应以修订后的 M1/M2 完整实施例核查最接近公开，并说明候选交互机制实际增加了什么；当前未形成新增专利的法律状态、同族或可专利性结论。
