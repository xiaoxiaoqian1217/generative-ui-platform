# JS智能场景候选设计

> 日期：2026-09-29｜性质：研究输入与候选设计，非业务确认、非实现规范、非专利法律结论。
>
> 需求条件与场景筛选框架沿用 [08](08-requirements-and-scenarios.md) 的 R1-R7 矩阵，本文只讨论JS方向候选。所有场景均为脱密表述，人的决策对象限定在"采集什么、核查哪里、是否继续"，不含打击授权与交战决策。

## 1. JS场景对专利机制的适配性

JS场景与民用无人巡检在需求结构上同构，但 R1 至 R3 与 R5、R6 的天然成立程度更高。

| 需求 | JS场景为什么强 |
| --- | --- |
| R1 人的增量不可替代 | 上级意图、人工情报、敌情背景大多不在系统数据链内，人的信息增益是真实且制度化的 |
| R2 运行中介入有时效价值 | 侦察窗口、暴露风险、任务节奏都强时效，事后审核可能直接失去战机或付出再次进入的代价 |
| R3 自主边界清晰 | JS自主系统有严格的授权链与规则交战程序，"什么必须找人"的边界制度上就是写好的 |
| R5/R6 影响与副作用 | 任务指令、资源调度、设备出动都是不可随意撤销的外部动作，失效传播与回执核查是刚需 |

同时有三个风险决定它适不适合做专利实施例。

1. 验证不可得：拿不到真实任务记录与专家访谈，[07](07-real-inspection-needs.md) 的取证计划无法执行，需求只能停在合理假设。
2. 保密审查：涉及国防利益的发明须走保密审查或国防专利渠道，公开文本必须脱密，实施例细节会被压缩。
3. 敏感性稀释：若实施例写成"打击授权、目标审定"，审查与舆论会聚焦伦理问题，交互机制本身反而被掩盖。

因此本文的取舍是：JS可以做候选场景，但首选非打击类任务，授权链只作为权限约束背景，不作为发明点。

## 2. JS无人系统候选场景（按推荐度排序）

### S1：无人侦察巡逻 - 清单外疑点复核与定向复查（首选）

侦察无人机或无人车按任务清单巡逻，回传图像中出现清单未覆盖的可疑目标或设施变化。

分析员结合人工情报判断"这是合法施工还是伪装目标"，指定复查角度、时机或邻近区域，系统转为可执行的追加侦察任务。

- 与 M1/M2 完全同构，可直接复用巡检的任务卡与 fixture 结构。
- 额外多一层目标关联修正：同一设施在不同批次图像中的身份合并与拆分，对应 M3 台账冲突。
- 时效性理由天然充分：平台在场时补采成本最低，离场后再次进入有暴露风险。

脱密表述建议："重点区域无人巡逻与疑点定向复查"。

### S2：战场搜救 - 搜索区域与优先级动态调整

无人机群执行搜救，分析员获得系统外的幸存者信号或情报碎片，调整搜索区域、重排优先级或改变采集方式（光电转红外）。

- R2 极强，是全部候选里"为什么现在就要人"最硬的场景。
- 风险：涉及多平台调度，执行端能力假设多；集群协调容易把专利写成调度平台，稀释交互课题。
- 适合做第二实施例验证迁移性，不适合首发。

### S3：基地与阵地周界无人值守巡检

周界机器人发现异常（围栏破损、不明痕迹、传感器数据矛盾），值守员复核并结合巡逻记录判断是入侵迹象还是设备故障或动物活动，决定加强监视点位或触发专项排查。

- 数据可得性相对最好：民用园区、油库、边境设施的安防巡检有大量公开资料可借，访谈可行性高。
- JS色彩可控，脱密容易，可直接落到"要地安防"这一军民两用表述。

### S4：战损评估 - 证据充分性判断

打击后无人平台回传毁伤图像，评估员判断证据是否足以支撑"任务完成"结论，不足时指定补充观测角度或转待专业核验。

- 直接对应 [07](07-real-inspection-needs.md) 第 3 节的需求 C（缺陷证据是否充分）。
- 链条后端接效果评估体系，外部依赖多；民用几乎无对应物，迁移验证差。
- 建议只作为机制变体记录，不进入首批实施例。

## 3. 不推荐的方向

- 目标打击授权与交战决策：法律上本来就必须有人，不存在"系统能否自动处理"的争议，做不了必要性检验；敏感度高，只做权限约束背景，不做实施例。
- 无人车队自主绕障与改道：与已撤回的"围挡绕行"同构，需求不成立。
- 电子战与频谱任务：数据完全不可得，且介入对象难以用现有五类对象表达。

## 4. 落地建议

1. 首发实施例用 S1/S3 的"侦察巡逻疑点复核"，脱密表述为"重点区域无人巡逻与疑点定向复查"，任务卡与民用巡检版大部分复用。
2. S2 搜救作为迁移验证场景，证明机制脱离"资产-构件"模型后在"区域-优先级"模型上仍成立。
3. 对比对照组保留三个：自主规则处理、事后离线审核、固定表单复核，JS场景同样要回答"为什么现在就要人"。

## 5. 前置决策事项

1. 专利申请渠道：普通发明专利还是国防专利渠道，决定实施例能写多细。
2. 普通渠道下，JS场景全部脱密为"要地安防、重点区域巡逻"表述，机制不变，业务外壳模糊化。
3. JS场景只作为机制可迁移性的证据，不替代民用场景的需求取证。
