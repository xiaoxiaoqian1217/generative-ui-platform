# 无人巡检真实介入需求：证据与候选场景

> 日期：2026-09-29｜性质：研究输入，非实现规范、业务确认或专利法律结论。
>
> 已确认方向仍为“地图优先、无人巡检”。具体行业和下列场景尚待验证；本文不扩大当前仓库的架构实施范围。

## 1. 撤回围挡作为主需求

原“P1—P5 巡检途中遇到围挡，请人决定绕行”的设定不足以证明人工介入必要性，撤回其主实施例地位。普通障碍若在自主导航能力和既定约束内，应由机器人处理，可保留为“不打扰用户”的对照。

新的筛选问题是：机器人已经能移动、定位和采集后，人究竟提供了什么不可缺少的事实、专业判断或任务授权？不能只因模型分数低就找人，也不能假设人看同一张模糊图就一定能判断。

## 3. 三类值得核实的需求

以下是根据证据形成的设计假设，优先考虑前两类，第三类用于检验协同是否真正闭环。

### A. 清单外疑点：专家发起追加取证

机器人按清单采集时，专家结合历史维修、构件用途或现场迹象，发现原任务没有覆盖的疑点。人应表达“查哪个对象、需要解决什么问题、补什么证据”，由执行系统负责可执行的移动与采集。

地图/构件模型用于选择准确部位、限定追加检查范围，关联已有证据并预览受影响任务。若现有检查规则已足以自动判断和补采，则无需人为增加审批环节。

### B. 台账与现场冲突：补充有来源的事实

现场对象与台账不一致，可能来自合法改造、资料滞后、对象关联错误或实际缺陷。用户若掌握系统未接入的维修记录，才有明确的信息增益；系统应展示冲突位置、对象身份、资料时间和现场证据。

交互允许补充记录来源、纠正关联或标记“待核实”。用户声明先作为待验证信息，不能一键改成权威正常状态；如相关台账已可自动查询，应先查询。是否修改主台账、谁有权限，须另外确认。

### C. 缺陷证据是否充分：追加专项核查或保留待核验

某次视觉发现可能不足以支持最终诊断。专业人员需要明确“尚缺什么证据”，决定追加可用测量、转交现场专项检查，或记录为待专业核验。不能把“确认/拒绝告警”设计成唯一出口。

地图用于绑定缺陷位置、采集视角、邻近构件和待查范围。界面应区分“已发现”“已补采”“待核验”“已核验”；取得新图像不等于诊断完成。系统未接入的派单或检测能力，只能表达为建议与待办。

## 4. 当前候选及交互验证方式

候选主线为：**资产巡检中的疑点追加取证与证据复核**。它不代表已经选定航空、桥梁或某个园区行业。

可先演练一条链：自动采集→专家选中疑点并说明核查目标→展示已有证据和缺口→选择可执行的追加检查→预览范围及后续影响→回传结果→专业核验或明确留待处理。普通巡检结果在仍有效时保留；不预设所有执行器都支持局部恢复。

尤其要验证“为什么现在就要人参与”：若机器人离场后难以补采、检查窗口即将结束或当前判断会改变后续采集，实时协同可能有价值；这些都须由业务记录证明。若采完统一审核效果相当，应采用离线审核，不为验证介入界面强行暂停任务。

## 5. 下一步取证与淘汰条件

先访谈实际检查员及结果使用者，围绕最近发生的一次案例，索取可脱敏的任务单、异常记录、补采记录和时间线，回答：

1. 原任务漏掉了什么？是谁、凭什么证据发现，普通自动规则能否处理？
2. 人补充的信息来自哪里，系统为何当时拿不到？没有这些信息会导致什么具体后果？
3. 为什么必须任务中处理？延后审核是否会增加再次进场、漏检或重复采集？
4. 用户实际修改的是采集目标、检查方法、对象关联还是结论？地图选择是否比列表足够有用？
5. 人仍无法判断时交给谁，如何保留责任与待核验状态？哪些任务可以继续？

将候选方案与“自动处理”“采完离线审核”“固定表单复核”比较，再确定原型。记录操作、补采、等待、误改及重复执行，不提前填写效果数字。

出现以下情况则淘汰或降级：只有普通避障；人没有额外信息或专业职责；离线审核同样有效；地图不帮助定位或限定作用范围；只能靠假设尚不存在的业务能力完成闭环。
